## What runs

`python3 scripts/t64_session.py run --fa3-sha256 <wheel hash>
--banked-at P1=<ISO> --banked-at P2=<ISO>` on the instance, from the repo
root, after deploy, preflight, the GCS write gate and
`scripts/gcp_bootstrap_instance.sh`. It is the P2 runner
(`scripts/t61_session.py`) with P4's steps: each step in its own process
through `scripts/run_phase.sh` (phase `t64_<NN>_<step>`), a log and a
`result.json` per step under `results/t64_p4_<UTC>/`, stop at the first
failure, `run --from STEP --session DIR ...` to resume. The FA3 hash and
both banking times are checked before step 1, so a missing one costs no GPU
time.

```bash
bash scripts/gcp_verify_gcs_writable.sh "$NAME" "$ZONE"
bash scripts/gcp_bootstrap_instance.sh "$NAME" "$ZONE" --suite-record   # first boot only; on Spot, b1
```

On the instance, from the deployed repo:

```bash
nohup bash scripts/session_exit.sh --log ~/p4.log -- \
    python3 scripts/t64_session.py run --fa3-sha256 <hash from the build> \
    --banked-at P1=<ISO, with offset> --banked-at P2=<ISO, with offset> >/dev/null 2>&1 &
```

The session runs under `scripts/session_exit.sh` (a real run refuses to start without it): on any exit, passed, failed, refused, killed or hung up on, its last act is to sync the logs, manifests and every `~/*.log` to the bucket (`logs/home/`, with the marker `logs/session_exit.json`) and then halt the VM, with no watcher on the Mac. The teardown pulls them from the bucket when the instance is halted or gone (step 2c).

Back on the Mac:

```bash
bash scripts/gcp_session_elapsed.sh "$NAME" "$ZONE" 462.42
bash scripts/gcp_teardown_session.sh "$NAME" "$ZONE" results/t64_p4
bash scripts/gcp_cleanup_check.sh
```

Then record the cost in `docs/spend_ledger.md`.

## Spot blocks (researcher's rulings, 7 Nov 2026)

P4 may run on Spot, and an interrupted Spot instance's session is discarded,
with no resume across instances. So the timed session runs in blocks, each
on its own boot and in its own session directory (`attnbench/lock/blocks.py`,
`scripts/t61_session.py run --lock --block`); their number, hours, caps,
halts and hard deletes are in "Time and cost" above, built by
`scripts/t64_card.py` with `scripts/t64_blocks.py`'s planner. The block spec is
in the lock file; `python3 scripts/t64_blocks.py --spec` prints its skeleton
from this card's step table (cells and the anchor are fixed at lock with the
grid). The prediction is committed once, in the block with `predict`, and
later blocks reuse it; ground truth's split follows its minutes and is set by
cell when the grid is locked.

**What holds the blocks together.**
- A block imports every earlier block's session directory (fetched from the
  bucket), each checked before anything runs: the same block spec, the same
  code commit, every step passed, not discarded. After its own preflight, its
  instance type, GPU and CPU model must be the earlier blocks'.
- Every ground-truth row carries its block's id and whether it is the anchor
  cell, which b2 and b3 both measure. After the last block, the post-session
  step compares the anchor between the blocks that ran ground truth
  (`python3 scripts/t64_session.py drift --lock docs/lock_values.json
  --block-dir <each block's session> --out results/t64_p4/block_drift.json`;
  `attnbench/analysis/block_drift.py`, adviser's ruling 2c of 11 Nov 2026):
  each block against the median of the other blocks' anchors, against T4.1's
  block drift bound read from the lock (working 6.77%, adviser's ruling of
  8 Nov 2026). A block without an anchor row, or with a NaN one, is refused. A
  block above the bound is a flag, not an exclusion: it is named, its rows are
  labelled "drift above bound", every block stays in primary scoring, each
  flagged block gets a sensitivity run without it, and the bound is never
  widened to pass. With two anchor blocks either may be flagged.
- A block whose instance restarted writes `INTERRUPTED_DISCARD.md` and is
  discarded alone. The block is rerun on a new instance; the others stand.

**The commands for block k** (the launch and teardown as above, with):

```bash
export GCP_HALT_MINUTES=<the block's halt> GCP_MAX_RUN=<the block's hard delete>m
```


Each block ends the same way: synced, then halted, by its own exit wrapper.
