# Launch card: the P4 session (T6.4, Sapphire Rapids + H100)

Prepared 28 Oct 2026 (task C15). Not launched, and not launchable yet: the
session runner refuses a real session until every task below is Done in the
deployed plan. The researcher launches it; nothing here runs on its own. No
step of this session has run on an H100, so every time and cost below is an
estimate.

## What runs

`python3 scripts/t64_session.py run --fa3-sha256 <wheel hash>
--banked-at P1=<ISO> --banked-at P2=<ISO>` on the instance, from the repo
root, after deploy, preflight, the GCS write gate and
`scripts/gcp_bootstrap_instance.sh`. It is the P2 runner
(`scripts/t61_session.py`) with P4's steps: each step in its own process
through `scripts/run_phase.sh` (phase `t64_<NN>_<step>`), a log and a
`result.json` per step under `results/t64_p4_<UTC>/`, stop at the first
failure, `run --from STEP --session DIR ...` to resume. The FA3 hash and
both banking times are checked before step 1, so a missing one costs no GPU
time.

## The commands

On the Mac, from the repo root, at the commit to deploy:

```bash
export ATTNBENCH_GCP_PROJECT=...          # this study's project, set outside the repo
export CLOUDSDK_CORE_PROJECT="$ATTNBENCH_GCP_PROJECT"
export GCP_HALT_MINUTES=330 GCP_MAX_RUN=6h GCP_RATE_INR_HR=462.42
NAME=attnbench-h100-t64-$(date +%Y%m%d-%H%M); ZONE=us-central1-a

bash scripts/gcp_cleanup_check.sh
bash scripts/gcp_launch_h100.sh "$NAME"            # ends when the VM is RUNNING
bash scripts/gcp_deploy_source.sh "$NAME" "$ZONE"
bash scripts/gcp_preflight_instance.sh "$NAME" "$ZONE" --quarantine
bash scripts/gcp_verify_gcs_writable.sh "$NAME" "$ZONE"
bash scripts/gcp_bootstrap_instance.sh "$NAME" "$ZONE"
```

On the instance, from the deployed repo:

```bash
python3 scripts/t64_session.py run --fa3-sha256 <hash from the build> \
    --banked-at P1=<ISO, with offset> --banked-at P2=<ISO, with offset>
```

Back on the Mac:

```bash
bash scripts/gcp_session_elapsed.sh "$NAME" "$ZONE" 462.42
bash scripts/gcp_teardown_session.sh "$NAME" "$ZONE" results/t64_p4
bash scripts/gcp_cleanup_check.sh
```

Then record the cost in `docs/spend_ledger.md`.

## Known before launch

- **Not launchable on this branch's base.** The strict stamp, the FA3 files
  and the async H100 launch path are on main (PRs #20 and #22). Launch from
  a commit that has them and this runner.
- **Most real step bodies wait for their tasks** and refuse with "not built",
  naming the task; `prereqs` stops the session before any is reached.
- **No FA3 means no session.** T6.4 depends on an FA3 backend (T2.16), so
  `fa3_import` stops the session rather than recording
  `dense_set_incomplete`. Running without FA3 is the researcher's call.
- **The null-kernel floor gate is read later.** Its multiple is fixed at
  lock; preflight only records P4's floor and its ratio to each published
  figure.
