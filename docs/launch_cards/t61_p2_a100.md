# Launch card: the P2 session (T6.1, Cascade Lake + A100)

Prepared 28 Oct 2026 (task C15). Not launched, and not launchable yet: the
session runner refuses a real session until every task below is Done in the
deployed plan. The researcher launches it; nothing here runs on its own. No
step of this session has run on an A100, so every time and cost below is an
estimate.

## What runs

`python3 scripts/t61_session.py run --banked-at P1=<when P1 was banked>` on
the instance, from the repo root, after deploy, preflight, the GCS write gate
and `scripts/gcp_bootstrap_instance.sh`. Each step runs in its own process
through `scripts/run_phase.sh` (phase `t61_<NN>_<step>`), so the session is
synced to GCS as each step ends. Each step writes
`results/t61_p2_<UTC>/<NN>_<step>/step.log` and `result.json`. The first
failure stops the session; after the fix,
`run --from STEP --session results/t61_p2_<UTC> --banked-at P1=...` resumes.

## The order rules the runner enforces

- `predict` comes immediately before `ground_truth`, so nothing is clocked
  between the sync and the hold.
- The runner holds until the instance clock is 65 s past the bucket's
  creation time for the prediction (60 s from plan Section 5.1, plus 5 s of
  margin), and the step refuses to start inside 60 s.
- The harness must report `first_clocked_block_started_at`, the first block
  of any kind it clocks, warm-ups included (Appendix A, 27 Oct 2026). A result
  carrying only the 25 Oct key is refused. The session's start is the
  earliest open time or stamp over every ground-truth attempt, so a rerun
  never moves it later.
- Once `predict` has passed, `--from` any step up to it is refused; a new
  prediction needs a new session.

## The commands

On the Mac, from the repo root, at the commit to deploy:

```bash
export ATTNBENCH_GCP_PROJECT=...          # this study's project, set outside the repo
export CLOUDSDK_CORE_PROJECT="$ATTNBENCH_GCP_PROJECT"
export GCP_HALT_MINUTES=360 GCP_MAX_RUN=6h30m GCP_RATE_INR_HR=297.47
NAME=attnbench-a100-t61-$(date +%Y%m%d-%H%M); ZONE=asia-southeast1-c

bash scripts/gcp_cleanup_check.sh
bash scripts/gcp_launch_a100.sh "$NAME"            # prints PROVISIONING_MODEL=FLEX_START or SPOT
bash scripts/gcp_deploy_source.sh "$NAME" "$ZONE"
bash scripts/gcp_preflight_instance.sh "$NAME" "$ZONE" --quarantine
bash scripts/gcp_verify_gcs_writable.sh "$NAME" "$ZONE"
bash scripts/gcp_bootstrap_instance.sh "$NAME" "$ZONE"
```

On the instance, from the deployed repo:

```bash
python3 scripts/t61_session.py run --banked-at P1=<ISO time, with offset>
```

Back on the Mac (use 350.14 if the launcher created SPOT):

```bash
bash scripts/gcp_session_elapsed.sh "$NAME" "$ZONE" 297.47
bash scripts/gcp_teardown_session.sh "$NAME" "$ZONE" results/t61_p2
bash scripts/gcp_cleanup_check.sh
```

Then record the cost in `docs/spend_ledger.md`.

## Known before launch

- **Not launchable on this branch's base.** The strict first-clocked-block
  stamp is on main (PR #20); `prereqs` checks for it. Launch from a commit
  that has it.
- **Most real step bodies wait for their tasks.** The structural probe, mask
  gate, components, K2 selection, the cell assembler and the ground-truth
  grid driver refuse with "not built", naming the task. `prereqs` stops the
  session before any of them is reached.
- **A Spot preemption** ends the session mid-step. Each step is synced as it
  ends, so the loss is the step in progress. If it is `ground_truth`, the
  committed prediction stands. Resuming `--from ground_truth` on a new
  instance needs the session directory copied back from the bucket first;
  no script does that yet, and the runner has not been tested that way.
- **The dry run** (`run --dry-run --session DIR`) exercises the order, the
  hold, the commit, the sync to a directory store and the late check on a
  CPU, with fakes for the GPU work.
